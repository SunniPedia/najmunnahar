# সহযোগী কার্যতালিকা — Vercel সংস্করণ

এটি আপনার আগের PHP ভিত্তিক ওয়েবসাইটটির **Vercel-সাপোর্টেড সংস্করণ**। UI, ডিজাইন ও সব ফিচার (সহযোগী তালিকা, কাজ যোগ/সম্পাদনা/মুছা, রিফ্রেশ) হুবহু আগের মতোই রাখা হয়েছে। শুধু PHP ব্যাকএন্ডকে Vercel-এ চলা যায় এমন **Node.js Serverless Functions**-এ রূপান্তর করা হয়েছে।

## কী কী পরিবর্তন হয়েছে (আপডেট: এখন সিঙ্গেল ফাইল, 500 এরর ফিক্স)

আগের ভার্সনে `@vercel/kv` প্যাকেজ ইনস্টল/রিজলভ না হওয়ায় `server 500` এরর আসছিল। এই ভার্সনে সেটা বাদ দিয়ে **একটি মাত্র ফাইল** (`api/data.js`) দিয়ে সব হ্যান্ডেল করা হয়েছে, যা সরাসরি Vercel KV-এর REST API `fetch` দিয়ে কল করে — কোনো npm প্যাকেজ ইনস্টল করার দরকার নেই, তাই ইনস্টল-ফেইলের কারণে 500 আসার সম্ভাবনা নেই।

| আগে (PHP) | এখন (Vercel) |
|---|---|
| `get_data.php` | `api/data.js?action=get_data` |
| `save_work.php` | `api/data.js?action=save_work` |
| `delete_work.php` | `api/data.js?action=delete_work` |
| `data.json` ফাইলে সরাসরি লেখা | Vercel KV (Redis)-এ REST API কলের মাধ্যমে সংরক্ষণ |
| `index.html`, `style.css`, `app.js` | অপরিবর্তিত (শুধু API URL গুলো `/api/data?action=...` করা হয়েছে) |

### ⚠️ 500 এরর কেন আসছিল, ও এখন কী হবে
KV ডেটাবেস কানেক্ট করা না থাকলে (`KV_REST_API_URL` / `KV_REST_API_TOKEN` না থাকলে):
- **আগের ভার্সনে**: `@vercel/kv` প্যাকেজ এরর ছুঁড়ে পুরো রিকোয়েস্ট 500 দিত।
- **এই ভার্সনে**: `get_data` অ্যাকশন সীড ডেটা (আপনার পুরনো `data.json`) দেখাবে — 500 আসবে না, শুধু সংরক্ষণ (save/delete) কাজ করবে না যতক্ষণ না KV কানেক্ট করা হয়।

তাই **ডেটা সংরক্ষণ (নতুন কাজ যোগ) কাজ করাতে হলে নিচের ধাপ অনুযায়ী KV ডেটাবেস অবশ্যই কানেক্ট করতে হবে।**

**কেন `data.json` ফাইল রাখা গেল না?** Vercel-এ সার্ভারের ফাইল-সিস্টেম প্রতিটি রিকোয়েস্টের পর রিসেট হয়ে যায় (read-only/ephemeral) — তাই PHP-এর মতো সরাসরি ফাইলে লিখে ডেটা সংরক্ষণ করা যায় না। এর বদলে একটি ছোট ফ্রি ডেটাবেস (Vercel KV) ব্যবহার করা হয়েছে, যা ঠিক আগের মতোই সব ডেটা স্থায়ীভাবে সংরক্ষণ করে।

## ডিপ্লয় করার ধাপ

### ১. প্রজেক্ট Vercel-এ আপলোড করুন
এই পুরো ফোল্ডারটি GitHub-এ পুশ করুন, তারপর Vercel Dashboard → **Add New Project** → আপনার রিপো সিলেক্ট করে ইম্পোর্ট করুন। (অথবা `vercel` CLI দিয়ে সরাসরি ডিপ্লয় করতে পারেন।)

### ২. একটি ডাটাবেস কানেক্ট করুন (Vercel KV বাদ হয়ে গেছে, এখন Upstash ব্যবহার করুন)
1. প্রজেক্ট → **Storage** ট্যাব → Marketplace থেকে **Upstash** সিলেক্ট করুন।
2. Database type: **Redis** বেছে **Create** করুন।
3. **Connect Project** ক্লিক করে এই প্রজেক্টের সাথে যুক্ত করুন।
4. Project → Settings → Environment Variables-এ গিয়ে দেখুন env var-এর নাম কী এসেছে — সাধারণত `KV_REST_API_URL`/`KV_REST_API_TOKEN` অথবা `UPSTASH_REDIS_REST_URL`/`UPSTASH_REDIS_REST_TOKEN`। `api/data.js` উভয় নামই চেক করে, তাই যেকোনোটা এলেই কাজ করবে।

### ৩. রিডিপ্লয় করুন
KV যুক্ত করার পর প্রজেক্টটি একবার রিডিপ্লয় করুন (Deployments ট্যাব → সর্বশেষ ডিপ্লয়মেন্টের পাশে ⋯ → **Redeploy**)। প্রথমবার `get_data` কল হওয়ার সাথে সাথে আপনার আগের `data.json`-এর সব তথ্য (Nazmun Nahar-এর সব কাজসহ) স্বয়ংক্রিয়ভাবে ডেটাবেসে সিড হয়ে যাবে।

ব্যস! আপনার সাইট এখন `https://your-project.vercel.app` -এ লাইভ, এবং আগের মতোই কাজ করবে — কোনো UI বা ফিচার পরিবর্তন হয়নি।

## লোকালি টেস্ট করতে চাইলে
```bash
npm install -g vercel
npm install
vercel dev
```
`vercel dev` চালানোর সময় এটি আপনাকে KV ডেটাবেস লিংক করতে বলবে (`vercel env pull` দিয়েও এনভায়রনমেন্ট ভ্যারিয়েবল লোকালে আনা যায়)।

## ফাইল গঠন
```
├── index.html          ← UI (অপরিবর্তিত)
├── style.css            ← স্টাইল (অপরিবর্তিত)
├── app.js                ← ফ্রন্টএন্ড লজিক (শুধু API URL পরিবর্তিত)
├── package.json          ← কোনো এক্সট্রা ডিপেন্ডেন্সি নেই (plain fetch ব্যবহার করা হয়েছে)
├── api/
│   ├── data.js            ← get_data / save_work / delete_work — সব একটি ফাইলে
│   └── seed-data.js         ← আপনার আগের data.json থেকে নেওয়া প্রাথমিক তথ্য
```
